通知 HTTP API 原型

要回答的问题：通知 API 要长什么样，才能同时服务桌面托盘客户端、网页铃铛和成员 Agent？重点检验四件事：通知 id 能否作为增量游标；实时通道断线后能否用 Last-Event-ID 补齐；已读是否按成员只存一份、Agent 是否不能改已读；客户端凭证是否只能读通知、标已读和查会话。

页面是纯浏览器内存模拟，刷新即重置。托盘连接只影响推送展示，通知本体始终可被 Agent 轮询拉到。SSE 实际服务每 25 秒发送 : ping 注释保活，本原型不计时。

引导场景

自由操作

工单事件直接改变模拟平台；设备操作会影响推送；HTTP 操作会记录完整请求和响应。
