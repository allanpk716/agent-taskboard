# 成员网页 mock（工单 #40）— 三个候选方向

三个目录各是一个自包含的可点击原型（打开各自的 `index.html` 即可，无任何外部依赖，手机浏览器直接用）。当前登录身份固定为 **李工（管理员）**，假数据覆盖：收件箱 6 条（六种原因各一条）、10 张工单（任务/反馈、开启/关闭、指派/未指派）、四份模板（含一份已停用）、完整标签字典（七个维度、别名）与几名成员及其成员 Agent。工单详情沿用访客网页拍板选中的对话流（`prototype/guest-web` 的 a 方案）：说明作为第一条气泡按字段展示，回复与居中灰色系统事件穿插，成员 Agent 头像带机器人角标。交互都是假的但尽量按真实规则演示：打标签会被字典拒绝并给近似值建议、写别名自动换标准值、建单缺必填只提醒不拦截、交付后轮到创建者验收、访客链接可创建/撤销/延期、模板保存报行号、Agent token 只显示一次。

- **方向 A（`a/`）— 左侧导航 + 紧凑表格，桌面优先**：像传统工单系统（Redmine 一类）。左侧固定导航栏一屏看全所有入口，收件箱和工单列表用信息密度高的表格，一页能扫很多行；工单详情是「左对话流 + 右信息栏」双栏，标签、指派、访客链接和操作常驻右栏，不用弹窗。手机上侧栏收成抽屉、表格自动变成带字段名的卡片。优点：桌面效率高、列可再扩展（时间、回复数等）；代价：手机上表格始终是妥协形态，长工单要滚很久才到底部操作。

- **方向 B（`b/`）— 移动优先卡片 + 底部标签栏**：像聊天/待办 App。顶部一栏标题，底部五个标签（收件箱 / 工单 / 大号「＋」建单 / 工具 / 我的），一切内容都是圆角卡片；收件箱每张卡片顶部是醒目的「原因」色条，一眼知道轮到我干什么；工单详情整页对话流，与访客网页观感完全同源，标签/指派/访客链接收进可展开的元信息区和一排小按钮；筛选 chips 横向滑动。桌面打开就是居中一列的手机版。优点：单手操作最顺、与访客端视觉家族最统一、建单入口最显眼；代价：信息密度最低，桌面端浪费空间，大量筛选条件只能一层层横向滑。

- **方向 C（`c/`）— 三栏邮件客户端式（导航 | 列表 | 阅读）**：像 Outlook/邮件客户端。左栏是收件箱和「保存的视图」（全部开启、指派给我、未指派、等待访客、已关闭），中栏是紧凑工单列表加筛选，右栏阅读和回复，选中一张单后中栏仍留着便于连续处理——初筛 Agent 巡检、批量验收这类「连着看很多张」的场景最顺手；模板、字典、设置、管理页借用右栏成为整页。手机上三栏退化为「列表 → 详情」钻取，导航藏进 ☰。优点：处理队列效率介于 A、B 之间，视图概念以后还能放自定义筛选；代价：窄屏要多点一次返回，三栏各自都偏窄。

## 裁决（2026-10-16，mockit 6kzwhv）

用户选中 **方向 B（`b/`）移动优先卡片 + 底部标签栏**，无批注。#41/#42 按 `b/` 实现。
