# Agent 技能只做附加的薄指针，不复制说明书、不带凭证

成员反映新开会话后 Agent 不知道有本平台：主人不贴工单指令、只说"看看轮到我的工单"时，Agent 想不起平台，也不知道说明书在哪。token 已经由 ADR 0007 存进环境变量，跨会话没有问题，缺的是"什么时候想起平台"。我们在平台上公开提供一份 Agent 技能（`{{BASE}}/skills/agent-taskboard/SKILL.md`）：只写触发场景、说明书地址和凭证所在的环境变量，规则仍然每次从 `/agent.md` 现读。技能经接入文案在签发时一并安装，「我的 → Agent」也常驻一段不带凭证的安装文字，用于补装和重装。

这部分修正了 ADR 0007 否决"存进各家 Agent 的记忆或配置文件"的理由：技能格式现在已有多家 Agent 支持，但并非全部，所以技能只是附加，接入文案、环境变量和工单指令仍然是所有 Agent 都能走的底线。

## Considered Options

- **厚技能（把说明书全文放进技能）**：省一次联网读取，但平台会自更新（ADR 0002），装在各人电脑上的副本会落后，而且无法回收，过期规则会让 Agent 做错事。
- **技能替代接入文案**：不能装技能的 Agent 就无法接入了。
- **让 Agent 写全局记忆**：各家做法不同，没有统一的触发机制，ADR 0007 已否决。

## Consequences

- 技能内容很少变，不做版本号和自动更新；需要更新时由成员重新发安装文字。
- 技能不带凭证、公开可读，平台地址由服务端按请求的基础地址填好，从哪个地址安装就指向哪个地址。
- 只面向成员 Agent；访客 Agent 是一次性访问，流程不变。
- 接入文案多了一步，验证回复要说明技能是否装上。
