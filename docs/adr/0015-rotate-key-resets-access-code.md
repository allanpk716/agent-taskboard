# 重置链接时连同访问码一起重置

ADR 0012 定下「换新地址」只换密钥，备注、认领和访问码都保留。实际用起来，成员重置链接多半是因为访客找不到链接、也记不清访问码，或者怀疑链接外泄了。访问码只存哈希，平台拿不回旧码，所以只换地址的话，成员能发出去的只有新链接，旧访问码要访客自己记得。我们改为：重置链接（`rotate-key`）在换新地址的同时重置访问码，清掉已记住的设备，并把新访问码返回一次，让成员一次把「新链接 + 新访问码」整段发给访客。成员 Agent 调同一个接口，也按这条规则走。

## Considered Options

- **保留 0012 的做法，只换地址**：对方已有设备不受影响，但遇到外泄时旧设备照样能进，访客忘了访问码时也还得再点一次「重置访问码」，两步才能发出完整的话。
- **网页上先换地址、再调重置访问码**：服务端规则不变，但两次调用不在一个事务里，中途失败会留下半套状态，Agent 也要自己记得调两次。

## Consequences

- 重置链接后，对方所有已登录设备和对方的 Agent 都要用新访问码重新进入。确认框和 Agent 说明书都要写明这一点。
- 未认领的链接没有访问码，重置链接只换地址；第一位打开并认领的人照常拿到访问码。
- 部分取代 ADR 0012 里「换新地址保留访问码」的说法；0012 关于密钥加密存放、随时再次复制转发文案的决定不变。
