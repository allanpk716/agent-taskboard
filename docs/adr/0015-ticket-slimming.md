# ADR 0015：新增瘦身，只移出附件、工单留在平台上

## 状态

已接受（2026-11-02 讨论定稿）。

## 背景

部门将有约 20 人使用平台。ADR 0014 的归档会把整张工单移出平台，只留墓碑，旧工单
因此无法在平台上查看、搜索；而部门需要靠老工单沉淀经验。空间增长的大头是附件（单个
上限 5MB、每条最多 5 个），说明、回复等结构化数据相对很小。2026-11-02 生产实测：数据库
1.5M、附件 4.4M、磁盘剩余 382G。需要注意的是，备份与数据同盘，每份都是完整数据库副本，
按保留策略最多约 47 份，所以数据库每增长 1 份，磁盘约增长 47 份；附件只有一份镜像（×2）。

## 决策

在归档之外新增**瘦身**：管理员手动筛选已关闭满 N 个月（默认 3）的工单，把其中的附件
（不含插图）导出成 zip（附件文件加一份清单，标明归属工单、所在回复和哈希）；下载并确认
保存后，只从服务器删除这些附件文件和它们的备份镜像，工单其余内容全部保留。

- 醒目标明：工单列表行内标记、详情页顶部横幅、成员 Agent 和访客读取接口都带上瘦身信息；
  原附件位置保留占位（文件名、大小、移出时间、包名）。
- 可恢复：上传瘦身包，校验后按工单逐张把附件放回。
- 瘦身不限制工单后续操作：可以重新打开（新附件照常保存，标记改为"部分附件已瘦身"）、
  多次瘦身，也可以再做整张归档。归档包里记下引用了哪些瘦身包，管理页提示需要一并保存。
- 瘦身生成、瘦身移出与瘦身恢复写进管理操作记录；瘦身包在服务器上暂存 7 天，到期自动删除；不发通知。
- 存储面板显示可瘦身的工单数和可释放的附件大小。

归档（整张移出）保持不变，两种操作并存：瘦身用于日常回收空间，归档用于需要彻底移出的场景。

## 考虑过的方案

- **只用归档**：旧工单无法在线查看、搜索，不符合知识沉淀的需求。
- **到期直接删除附件、不导出**：附件里常有日志和现场证据，删除后无法恢复，所以要求先有
  离线副本。
- **定时自动瘦身**：做不到"下载确认后再删"，所以改为由管理员手动触发。

## 后果

- 工单正文永久留在平台上，数据库持续增长，并被约 47 份同盘备份放大。备份的位置和异机方案
  由部门统一安排，本次不改变。
- 要完整还原一张先瘦身、后归档的工单，需要同时保存它的归档包和相关的瘦身包。
