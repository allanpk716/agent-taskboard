# 桌面客户端用专门的客户端凭证，只能读通知、标已读

桌面客户端要长期常驻、调用通知 API，需要一把凭证。我们新增第三种成员凭证「客户端凭证」：挂在成员名下，只能读取通知、未读数和标记已读，不能读写工单，也不产生任何时间线上的操作，因此不必署名，也不会冒充本人。它只能在网页本人会话里签发：客户端在 127.0.0.1 上监听，打开浏览器让成员确认「连接这台电脑」，再凭一次性 code 和 PKCE 换取凭证。ADR 0003「API token 一律是 Agent」的规则保持不变。

## Considered Options

- **复用成员 Agent token**：权限是整个成员的，泄露代价大；客户端标已读会被当成 Agent 的操作，与 ADR 0003 的语义冲突。
- **device code（手抄验证码）**：内网同机场景下多一步人工，没有必要。

## Consequences

- 客户端凭证长期有效，直到撤销。成员在网页「我的」里按电脑（主机名）查看和单独撤销；客户端「退出登录」时撤销自己的凭证。
- 账号停用、管理员重置密码时，连同该成员的全部客户端凭证一起撤销；成员自助改密时不撤销。
- 已读状态按成员只存一份，客户端、网页铃铛共用；一位成员可以在多台电脑上各持一把凭证，同一条通知在每台上都会弹出。
