# ADR 0020：Orca 插件接替桌面客户端，沿用客户端凭证并放开只读清单接口

日期：2026-11-20

## 状态

已接受。取代 [ADR 0011](0011-desktop-client-standalone-distribution.md)；改写 [ADR 0004](0004-desktop-client-credential.md) 中客户端凭证的权限边界。

## 背景

部门成员日常都在 Orca 里工作，而 Windows 桌面客户端只覆盖 Windows 电脑，还要单独维护安装、自更新、Toast 注册和发布产物。Orca 的插件体系可以做到桌面客户端做的所有事：常驻 worker 订阅通知流、弹桌面通知、在状态栏显示未读、在侧边栏面板列出工单，并在浏览器里打开工单页。成员还希望在提醒的地方顺便看到收件箱的大致情况，而不只是看到通知。

## 决定

- 桌面客户端下线：删除 `cmd/taskboard-client` 及 Windows 相关代码，Release 不再产出 exe，`latest.json` 去掉 `client` 条目，去掉网页和文档里的下载入口。已安装的旧 exe 不主动作废，但不再更新。
- 「Orca 插件」接替它，成为唯一的常驻提醒通道。插件在单独的仓库 `allanpk716/taskboard-orca-plugin` 里开发，独立打 tag，通过 `orca plugin install` 安装。
- 插件沿用客户端凭证，签发流程（网页确认 + 本机回环 + PKCE）不变。`client_scope` 在通知之外，放开现有的只读清单接口：`GET /inbox`、`GET /inbox/waiting-on-counterparts`，以及只限 `collaborator=me&status=open` 这一个组合的 `GET /tickets`（协作中）。插件自己把这些清单拼成概览。仍然不能读说明、回复、附件，不能改动工单，不署名。
- 插件持有通知流连接时算作「客户端在线」，网页铃铛照旧避让。

## Considered Options

- **插件用成员 Agent token**：能看到全部内容，但权限是整个成员的（能回复、能建单），泄露代价大；提醒通道标已读会被当作 Agent 的操作，与 ADR 0003、0004 的语义冲突。
- **新做一个聚合的「我的概览」接口**：插件一次请求就能拿到全部数据，字段也收得最窄，但要多维护一套推导，口径可能和网页收件箱慢慢走偏。
- **新造一种「插件凭证」**：和扩大后的客户端凭证只差一个名字，徒增概念。
- **插件放在本仓库子目录**：接口改动和插件可以同一个 PR，但 Orca 从 Git 安装时默认取最新的 `vX.Y.Z` tag，会和服务端发版的 tag 冲突。

## Consequences

- 客户端凭证从"只读通知"变成"只读通知 + 只读的三份清单"。概览里有工单标题，凭证泄露时暴露面比以前大，但仍然碰不到说明、回复和附件。
- Orca 的桌面通知不支持点击跳转，所以要跳到工单页，得在插件面板里点；状态栏点一下打开面板。
- 不用 Orca 的成员不再有常驻提醒，只剩网页铃铛的浏览器弹出提醒。
