# 工单文案永不带 token，token 在签发时经接入文案一次性存进 Agent 的环境变量

成员抱怨复制工单给 Agent 后还要手动替换 token。我们没有把 token 塞进工单文案，而是把凭证和工单拆开：签发 token 时生成一次性的接入文案，让 Agent 自己执行 `setx TASKBOARD_TOKEN <token>` 长期保存；之后每张工单的工单指令和交接文案只引用 `TASKBOARD_TOKEN`，不含凭证。

## Considered Options

- **工单文案里带上复制者的 token**：交接文案会转到同事手里，同事的 Agent 就会以复制者的名义操作，破坏 ADR 0003 的署名可信；而且服务端只存 token 的哈希，事后取不回明文。
- **每次复制都临时签一把新 token**：token 越积越多，没法管理和撤销。
- **由成员自己在终端设置环境变量**：对使用者有门槛，接入文案只把它作为 Agent 无法执行命令时的后备。
- **存进各家 Agent 的记忆或配置文件**：每种 Agent 做法不同，无法给出统一说明。

## Consequences

- token 会出现在 Agent 的对话记录里；内网可以接受，泄露时可以随时撤销或「换新」。
- 变量名固定，同一台电脑同一个系统用户下的多个 Agent 共用一把 token，署名分不出是其中哪一个；真有需要时再扩展。
- 接入文案只显示一次，丢了就用「换新」：撤销旧 token，签发同名新 token，生成新的接入文案。

后续：技能形式的补充见 ADR 0013，本条"工单文案永不带 token"不变。
