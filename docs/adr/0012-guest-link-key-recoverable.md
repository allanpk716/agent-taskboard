# 访客链接密钥加密存放，成员可以随时再次复制转发文案

访客链接的密钥原来只存哈希，完整链接只在创建时出现一次。访客常常忘了这件事，或者找不到链接了，成员只能手打一大段话重新解释，或者再建一条链接。我们改为另外用服务端密钥加密保存密钥，成员（以及成员 Agent，和网页用同一份）在链接有效期间可以再次复制同一条链接的转发文案，文案每次按当前状态生成。校验仍然只靠哈希。

## Considered Options

- **再次复制就撤销旧链接、新建一条**：密钥只出现一次的原则得以保留，但对方翻出旧消息一点就失效，认领关系也会丢失。
- **同一条链接换一把新密钥**：备注、认领、访问码都能保留，但旧地址照样失效。这个办法只留给本功能上线前、没存密钥的老链接（「换新地址并复制」）。

## Consequences

- 数据库连同加密密钥一起泄露时，所有未过期的访客链接都能被还原。这个风险可以接受，因为一条访客链接只能访问一张工单。
- 加密密钥由服务端首次启动时自动生成，放在数据目录里，和数据库文件分开存放。密钥文件丢了，链接照常能用，只是全部退化成老链接，要先换新地址才能再次复制。
- 备份会连同密钥文件一起备份（现有备份本来就不只有数据库，还镜像了附件），恢复后链接仍能直接复制。代价是备份目标泄露也等于“数据库连同密钥一起泄露”，按上面第一条接受。没有密钥文件的旧备份恢复后，链接按老链接处理。
- 「换新地址」接口不限于老链接：遇到链接疑似外泄时，也可以对新链接换地址。界面上只对不能直接复制的链接显示这个按钮。
