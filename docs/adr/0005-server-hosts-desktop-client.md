# 桌面客户端由 taskboard 服务端代管分发与更新

桌面客户端沿用 ADR 0002 的发布方式（`client/v*` tag，GitHub Release 与 UpdateHub 双发布源，manifest 带 SHA256），但成员电脑不直接访问这两个源：管理员更新平台时，服务端按已配置的更新源把客户端包一起拉回、校验后存进数据目录，再由服务端提供版本查询和下载。客户端只和自己登录的服务端通信，首次安装和自动更新都从这里取。这样同事电脑不需要能访问 GitHub 或 UpdateHub，也不用配置镜像和代理；客户端什么时候换版本，跟着管理员手动更新的节奏走，和 ADR 0002 一致。

## Considered Options

- **客户端自己查 UpdateHub 和 GitHub**：每台电脑都要能访问两个源、各自配置镜像和代理，国内访问 GitHub 又不稳定；客户端版本也会脱离管理员的控制，平台还没更新，客户端就可能先换了版本。

## Consequences

- 服务端的更新器要多管一个组件：客户端独立版本，不和前端、后端绑定，但跟它们在同一次管理员更新里检查。
- 客户端自动、静默地更新到服务端代管的版本，成员不需要做任何决定。自动更新被拦截时，服务端在 `/session` 里返回 `min_client_version`，版本低于它的客户端停止拉取通知，并提示成员重新下载。
- 客户端是免安装的单个 exe，自己安装到用户目录，不需要管理员权限。它没有签名，首次运行要点「仍要运行」；之后的更新由客户端自己下载，不带 Mark-of-the-Web 标记，不会再弹 SmartScreen。
