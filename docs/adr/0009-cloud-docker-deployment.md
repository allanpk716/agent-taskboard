# ADR 0009：从内网 Windows/NSSM 部署迁到公网云服务器 Docker 部署

日期：2026-10-23

## 状态

已接受。部分被取代：镜像携带桌面客户端的部分由 [ADR 0011](0011-desktop-client-standalone-distribution.md) 取代；回滚方式由 [ADR 0010](0010-cloud-release-and-deploy.md) 取代（换回旧 tag 的同时恢复升级前备份）。

## 背景

平台原本部署在公司内网 Windows 服务器上，由 NSSM 托管进程。成员在外网打不开网页，Agent 按 ADR 0008 写好草稿后，成员不能查看原文并亲自确认；外部反馈入口也无法访问。曾考虑让 Agent 通过 TOTP 代成员确认，但成员确认的会是 Agent 的转述，不是草稿原文，这个渠道既复杂又削弱「只认本人确认」的原则。

## 决策

把平台迁移到公网云服务器，用 Docker 镜像部署。服务仍只监听 `127.0.0.1`，由宿主机 Caddy 提供 HTTPS 并反代；数据目录放在宿主机数据卷里，配置只读挂载，容器以非 root 用户运行。升级不再原地替换二进制，而是先做更新前备份，再拉取新镜像并重建容器。镜像携带与后端同版本的 Windows 桌面客户端安装包，启动时装入数据目录，供成员下载和客户端自动更新。

## 后果

- 成员可在手机上直接打开草稿的 `preview_url`，确认的是平台原文；TOTP 确认渠道不再实施。
- 公网反馈入口可被公司外部访问，同时接受更大的公网暴露面，依赖验证码、失败锁定、限流、反馈防刷和 HTTPS 等加固措施。
- 放弃内网 NAS 作为当前备份目标：迁移初期备份仍留在云服务器挂载的数据卷内，并用每日磁盘快照作临时补救；异地备份另开后续方案。
- 容器 host 网络让服务看到的回环对端就是宿主机 Caddy，现有「只信任回环对端带来的 `X-Forwarded-For`」规则继续成立。
- 镜像升级回滚采用换回上一个镜像 tag；原地更新器的 exe 替换和 rollback 流程不再适用于容器部署。
