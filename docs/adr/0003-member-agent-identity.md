# 本人与成员 Agent 按凭证类型区分：网页登录是本人，API token 一律是 Agent

成员的回复和操作必须能看出是本人写的，还是他名下的 Agent 写的。成员 Agent 不是独立账号，而是挂在成员名下、权限与成员相同的具名凭证。平台按凭证类型判定来源：通过网页登录会话的操作算本人；通过 API token 的操作，一律记为签发这个 token 的那个成员 Agent。成员没有供本人使用的 API token，因此本人用 curl 或 CLI 调接口时也会显示为他的 Agent。我们接受这一点，换来的是 Agent 无法冒充本人。

## Considered Options

- **Agent 在请求中自报身份**：做法简单，但标注靠 Agent 自觉，迟早会有漏标。
- **独立的 Agent 账号**：会带出 Agent 能否被指派、权限怎么设、成员离职后 Agent 归谁等问题，超出了记录平台的范围。

## Consequences

- 创建和撤销 Agent token、创建成员账号，只能在网页上操作，Agent 无法再给自己或别人签发凭证。
- 访客只有一把链接密钥，平台分不出访客本人和访客的 Agent，所以访客的 Agent 只能自报，平台把它当作未经核实的信息展示，界面上也要和平台认证过的成员 Agent 区分开。
